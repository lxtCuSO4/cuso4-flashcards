# 编辑器图片与预览实施计划

**Goal:** 在现有卡片编辑器中插入本地图片，保存前预览基础卡与各编号填空卡。

**Architecture:** 图片在编辑期间仅保留为有大小限制的内存草稿。预览复用 CardContent 和 ClozeParser；保存时图片文件、媒体记录及笔记引用由同一数据库事务协调。取消编辑不产生正式媒体。保留现有排程、填空删除确认和未保存退出保护。

**Tech Stack:** Flutter、Drift、现有 file_picker、crypto，无新依赖。

本次用户已认可继续实现图片插入和预览；沿用当前工作区、视觉体系及预算限制，当前会话直接实施，不使用子代理。

- [x] 图片准备：PNG/JPEG/GIF/WebP，检查实际编码和可解码性，单张最多 10 MiB、1600 万像素，草稿合计最多 30 MiB；拒绝失败后保留文字。
- [x] 媒体保存：仅落盘正文仍引用的草稿，哈希去重，同一笔记重复引用只计一次；保存失败回滚新文件/记录，已有共享文件保持可用。
- [x] 编辑界面：每个内容字段下设置插图按钮，在选择位置插入标准 img 标签；选择/保存期间阻止重复操作和退出。图片说明列出格式、限制、预览入口。
- [x] 预览界面：使用未保存文本与图片，基础卡显示答案，填空卡可切换编号，切换后重新隐藏答案；不创建笔记或写学习记录。
- [x] 针对性验证：图片验证/共享引用/事务回滚、草稿图片预览、填空切换及无写入；运行相关现有仓储与媒体测试、静态分析。
- [x] 构建新的 ARM64 测试 APK，核验包标识、版本、签名及代码哈希，冻结到新的文件名；更新使用说明与进度并本地提交。

实现细节以现有仓储事务与原生安全渲染为准。预览不运行任意 Anki 模板、CSS、脚本或远程资源。快捷填空、全局搜索、批量管理不在本轮范围。
